> 我给团队编了一根牵引绳。需求、契约、证据、方案，全走一个 git 仓；每台机器上的 AI 开工前先读它，人只负责拍板。

---

## 一、你大概率见过的现场

你的 AI 在写前端，同事的 AI 在写后端。昨天刚对齐的接口，今天双方已经各改了三版。

- 前端 AI 按周二的老文档调 `/login`，后端周三就改了返回结构，联调那天爆炸
- 谁改的、为什么改、会影响谁，没人说得清，只能拉会对齐
- 两边的 AI 都说"完成了"，但没有证据，验收变成信不信
- "当时为什么这么定？"答案在聊天记录里、在某个人脑子里，就是不在仓里

人对齐的速度，追不上 AI 生成的速度。

## 二、问题出在哪：协作信息有两类

一类是**状态**：谁在干什么、接口长什么样、凭什么说做完了。它高频、结构化，而且只有一个写入方。

另一类是**共识**：整体方案怎么定、为什么这么定、系统之间怎么对接。它低频、叙述性，靠多方参与慢慢成形。

现在的工具基本只解决了第一类。状态能同步了，共识还在靠记性和开会。于是一个 AI 窗口开工时，大脑里只有自己那张单。

## 三、我的答案：把它变成一个 git 仓

不搭服务器，不做配置中心。需求、契约、证据、方案、共识全部放进一个普通 git 仓，每台机器 `git push/pull` 就是全部通讯。

绳只做三件事：给方向、拦住越权、传播共识。机制上有两条。

**三道门**，写入路径和收敛检查双重强制：

- 证据门：说"完成"必须带证据，git commit 会被真实验证
- 背书门：破坏性接口变更必须人确认，AI 自己批一律拒
- 拍板门：整体方案必须人拍板，AI 自说自话不算共识

**四个时机**，定义 AI 的动线：

- 上绳：我是谁、做什么系统
- 开工：干什么、被谁卡住、哪个方案等我表态
- 干活：干到哪、凭什么说做完
- 收尾：全局还差什么

人只做两件事：拍板、看板。

## 四、上手只要两步

不用记命令。工具装好之后，把一段话丢给自己的 AI 助手（opencode、Claude Code 都行），剩下的它来问、它来跑。

第一步，维护者（一个人）：建仓、注册自己，然后把仓库地址发出去。

第二步，其他人（同事、PM、每台机器上的 AI 窗口）：把仓库地址交给自己的 AI，按打印出的协议自助上绳。

```
我要加入一个已用 OuSheng 上绳的项目：
1. 向我要中央仓地址，clone 到本机。
2. 运行 ousheng join，按打印出的协议执行：
   问题在对话里问我，命令你来跑。
3. 完成后汇总：我的身份/系统/角色，下一步干什么。
```

公司里那一堆"先配置环境再协作"的活，基本都省了。机器坏了也不怕：重新拉一遍仓库，再把同一段话丢一次。

## 五、凭什么信它，它又明确不保证什么

它已经真跑过一遍：四台机器、一个裸 git 仓，中间扔进 24 个突发场景，假冒他人身份、机器直接损毁、依赖成环、伪造证据、批量单雪崩，每一个都被机制接住。全程没有共享数据库，没有中心服务器，没有任何额外基础设施。

门的强度是"写路径校验加审计线索"，手改文件可以绕过，兜底在 git 审计和仓库权限。绳只保证一致和收敛，不保证目标本身是对的；方向对不对，永远是人判断。

它明确不做：自动生成契约、语义合并、讨论内容管理、中心验证管线。发散归对话层，绳只存收敛之后的骨架。
